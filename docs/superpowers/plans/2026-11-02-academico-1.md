# Acadêmico, entrega 1: plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** turmas por produto, alunos e matrículas, cadastro de professores, contagem de ativos e importação da planilha `.xlsx`.

**Architecture:** o módulo `src/modulos/academico/` segue o padrão do Comercial:
- `esquemas` (Zod);
- `regras` (funções puras e testadas);
- `importacao` (leitura e planejamento puros, mais a gravação no servidor);
- `servicos` (Prisma);
- `acoes` (Server Actions);
- `componentes`.

As rotas ficam em `src/app/(app)/academico/`.

**Tech Stack:** Next.js 16 (App Router), Prisma 7 + MySQL, Zod 4, Vitest, exceljs 4.4.0.

**Spec:** `docs/superpowers/specs/2026-11-02-academico-1-design.md`

## Global Constraints
- Tudo em português: código de domínio, interface e mensagens.
- Tabelas `snake_case` no plural via `@@map`, ids `cuid`, `criadoEm`/`atualizadoEm`, e datas sem hora em `@db.Date`.
- **Dados pessoais:**
  - nunca em URL, log ou `diff` de auditoria;
  - o filtro de alunos roda só na tela;
  - erros de importação citam só aba e linha.
- Migration gerada com `prisma migrate diff` a partir do schema em HEAD, com timestamp posterior a todas as pastas de `prisma/migrations`.
- Página de servidor não importa constante de arquivo `"use client"`.
- Commits: `git commit -F <msg> -- <caminhos>`, só com arquivos próprios, mensagem terminada em `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Build: `npx next build --webpack`.

## Review Focus
1. **Reimportar a mesma planilha não pode duplicar** turma, aluno nem matrícula. Teste em `planejarImportacao`: com o estado existente, tudo vira "atualizar".
2. **Homônimos com telefones diferentes** são pessoas diferentes. Teste em `planejarImportacao`.
3. **Valores que o Excel entrega com outro tipo:**
   - CRM chega como número `28117` e deve virar `"28117"`;
   - telefone chega como número;
   - data chega como `Date` ou como texto `dd/mm/aaaa`.

   Testes em `lerAbas`.
4. **Linhas vazias no fim da aba** (a aba tem 127 linhas e só 80 alunos) são ignoradas, não viram erro. Teste em `lerAbas`.
5. **Curso sem produto escolhido** bloqueia a gravação com uma mensagem clara. Teste em `planejarImportacao`.

### Task 3: Importação pura
**Files:**
- Create: `src/modulos/academico/importacao/ler.ts` (+ teste).
- Create: `src/modulos/academico/importacao/planejar.ts` (+ teste).

**Interfaces (produz):**
- `type Aba = { nome: string; linhas: unknown[][] }`, já com os valores das células.
- `type LinhaImportada = { aba: string; numero: number; curso: string; nome: string; turma: {nome; ciclica} | null; situacao: {...} | null; crm; telefone; dataInicio: Date | null; dataFormatura: Date | null; vigencia; plano; observacoes }`.
- `lerAbas(abas: Aba[]): { linhas: LinhaImportada[]; abasLidas: string[]; abasIgnoradas: string[]; erros: ErroLinha[] }`, com `ErroLinha = { aba: string; numero: number; mensagem: string }`.
- `sugerirProduto(curso: string, produtos: { id; nome; sku }[]): string | null`.
- `planejarImportacao(linhas, mapeamento: Record<string, string | "ignorar">, existentes: { turmas: {id; produtoId; nome}[]; alunos: {id; nomeBusca; telefone; crm}[]; matriculas: {id; alunoId; turmaId}[] }): Plano`.

O `Plano` tem:
- `erros: ErroLinha[]`;
- `avisos: ErroLinha[]`;
- `turmasNovas: {chave; produtoId; nome; ciclica; situacao; dataInicio}[]`;
- `alunosNovos: {chave; nome; nomeBusca; telefone; crm}[]`;
- `alunosAtualizar: {id; telefone?; crm?}[]`;
- `matriculas: {alunoRef; turmaRef; dados}[]`, em que `alunoRef` e `turmaRef` são `{id}` ou `{chave}`;
- `ignoradas: number`.

Detalhes:
- As colunas são reconhecidas pelo cabeçalho normalizado (`nomeBusca`): `nome`, `curso`, `turma`, `formacao`/`status`, `crm`, `telefone`, `data de inicio`, `data de formatura`, `vigencia`, `plano da pos-graduacao` e `obs`.
- Uma aba só é lida se o cabeçalho tiver nome, curso e turma.
- Linhas sem nome nem curso são ignoradas sem erro.
- Datas aceitas: `Date` ou `dd/mm/aaaa`, gravadas ao meio-dia UTC.

- [ ] Testes de `lerAbas`:
  - lê só a aba que tem as colunas;
  - ignora linhas vazias no fim;
  - CRM numérico vira texto e telefone numérico vira dígitos;
  - situação inválida e turma vazia viram erro com aba e linha, sem o nome.
- [ ] Testes de `planejarImportacao`:
  - curso sem mapeamento gera erro "Escolha o produto para o curso …";
  - "ignorar" conta em `ignoradas`;
  - turma nova recebe `em_andamento` quando há ativa e `concluida` quando só há formados e cancelados;
  - turma cíclica fica sem data;
  - reimportação com estado existente gera zero novos;
  - homônimo com telefone diferente gera aluno novo;
  - mesma pessoa e mesma turma repetidas geram aviso e uma matrícula só.
- [ ] Teste de `sugerirProduto`: "PÓS - TC&T" → produto de SKU `PG001TCT`; "PÓS - PSQ EAD" → nome com "Psiquiatria EAD"; "PÓS - PSQ HIBRIDO" → nome com "Psiquiatria Híbrido".
- [ ] Implementar, rodar os testes e commitar.

### Task 4: Serviços e ações
**Files:**
- Create: `src/modulos/academico/servicos/acesso.ts`, `turmas.ts`, `alunos.ts`, `professores.ts`, `visao.ts` e `importacao.ts`.
- Create: `src/modulos/academico/importacao/xlsx.ts`, com `lerArquivoXlsx(buffer: ArrayBuffer): Promise<Aba[]>`, usando o exceljs e convertendo fórmula, rich text e hyperlink em valor simples.
- Create: `src/modulos/academico/acoes/turmas.ts`, `alunos.ts`, `professores.ts` e `importacao.ts`.
- Modify: `package.json`, adicionando `exceljs: 4.4.0`.

Regras dos serviços:
- Toda função recebe `ator: UsuarioAtual` e checa a permissão.
- Turma: nome único por produto entre não excluídas, e exclusão só sem matrículas.
- Matrícula: única por (aluno, turma), com mensagem "Este aluno já está nesta turma.".
- A auditoria guarda `diff: { campos: string[] }`.
- `visao.ts`, função `obterVisaoGeral()`: produtos não excluídos com turmas, cada um com as turmas (situação, ativos e total), mais o total geral, usando `contarAtivos`.
- `importacao.ts`:
  - `analisarPlanilha(ator, buffer)` devolve a prévia (abas, contagens, cursos com sugestão e erros);
  - `importarPlanilha(ator, buffer, mapeamento)` grava o `Plano` em uma `$transaction` (timeout de 60 s) e devolve as contagens;
  - se o plano tiver erro, lança `ErroNegocio`.
- Ações: arquivo de até 5 MB e extensão `.xlsx`; o mapeamento vem nos campos `produto:<curso>`.

- [ ] `npm run typecheck` e commit.
